## Characterization regressions carried forward

The thirteen original defect probes are covered by executable fixed-behavior tests:

1. Raw network TypeError now retries the same operation, status first (`project-preview-recovery`).
2. Idle/timer cancellation settles; all capture waits remove listeners (`project-preview-recovery`, `project-thumbnail-capture`).
3. Four PENDING polls no longer discard ownership or durable bytes; stage/reload/worker completion is tested (`project-preview-recovery`, browser pipeline suite).
4. Array scans yield and stop by relevant visible-type budget, preserving later visible rows (`project-thumbnail-capture`, browser capture suite).
5. Saved/runtime layers are normalized by ID without double rendering faithful pixels (`project-thumbnail-capture`).
6. Saved camera and actual consumed renderer generation fence runtime drift (`project-thumbnail-capture`).
7. Same-revision captures own different immutable objects (`project-preview-operations`).
8. Late worker failure cannot downgrade another READY (`project-preview-operations`).
9. Revision-only PATCH can no longer fail an unrelated attempt (`project-preview-operations`).
10. Superseded uploads cannot delete the previous READY fallback (`project-preview-operations`, serving tests).
11. PNG signature alone, bad CRC, malformed/truncated compressed data, invalid scanlines and excessive dimensions fail validation (`project-preview-operations`).
12. READY PUT replay revalidates actual bytes and current authorization; missing storage is not a false success (`project-preview-operations`).
13. MISSING/UNKNOWN inventory is read-only and includes repair proposals; no broad state rewrite is performed (`project-thumbnail-serving`).

Additional review regressions cover transaction rollback, upload/journal crash boundaries, late leases, exact historical receipts, actor/org/project mismatch, ACL generation/revocation, authenticated 304, changed storage context, 401 pause, bounded HTTP/body deadlines, quota-neutral promotion, late logout stage/put/promotion, same-account login ABA, 401 preservation, purge-failure fencing, abandoned-stage expiry and shared-worker domain failures.

## Measured evidence, not general SLO certification

`../operations/project-preview-capture-evidence/` records 88 browser capture cases, eight framing characterizations, actual mounted PNG/screenshot evidence and qualified p50/p95/p99 measurements. The same-pixel simple baseline alternates the actual historical implementation with the new implementation. Twenty samples per engine/profile and a shared headless host are insufficient to certify the proposed physical-desktop/mobile SLO, full application latency, or tail behavior.

The mounted zero-difference oracle verifies pixels after the historical independent X/Y normalization. A non-16:9 editor can still turn circles into ellipses; the retained html2canvas fallback uses its historical centered crop. This refactor does not introduce a crop/contain redesign or claim geometric preservation across arbitrary aspect ratios.

The new path performs one PNG encode. No resolution/format reduction or arbitrary visible-row sampling was used to manufacture a gain. The global preserveDrawingBuffer patch remains unchanged. Offscreen worker encoding is not introduced because equivalence across supported renderers has not yet been established.

## Preconditions before merge/release

- Check required CI against the exact final combined commit, including the preview workflow and the existing save, project, lifecycle, browser and build gates.
- Re-run affected tests after integration/conflict resolution. Do not use a green save-only SHA as evidence for the later preview SHA.
- Migration 0040 follows 0039. Neither migration has been applied by this change. Use the protected audit/apply/post-validation lifecycle and explicit authorization for each exact audited hash.
- Preview readers remain compatible before 0040; new preview admission/frontend flags default off. Keep production capture disabled until its schema, retention, processing and acceptance decisions are complete.
- Evaluate the independent JSON cutover requirements documented in `durable-project-saving.md`. Preview compatibility does not by itself prove that the JSON cutover is safe before 0039/its flags.
- Production branch merge may trigger deployment. Confirm actual production bindings and feature configuration before treating merge as safe release; do not infer them from CI or Preview URLs.
- No worker/queue/cron/binding is provisioned here. The existing scheduled worker can call both recovery domains with separate flags. Do not enable image admission without an approved recovery/retention strategy.
- Objects and receipts are conservatively retained, with no automatic pixel GC. Approve a reference-aware retention policy before deleting anything.
- The three affected real projects remain unaudited individually. Read-only inventory and a separately approved conditional repair are required; code approval is not permission to mutate them.

A conditional instruction to merge when all functionality and plan criteria are satisfied must be evaluated against these explicit remaining boundaries. Do not describe synthetic passing tests as completed production acceptance or claim that the three real cards have been repaired.

## Error-copy ratchet

The strict scanner's rule/exclusion sets are unchanged. Two obsolete baseline allowances are removed: raw Error.message in the old capture module and response.text in the old thumbnail client. Three exact internal-diagnostic counts are recorded for the new staging method and numeric metrics payload (`stage` is the scanner's matching identifier). Those values are internal storage/telemetry only, never composed into public error copy; the metadata allowlist tests and final independent source review cover this boundary.
